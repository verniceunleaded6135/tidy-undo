# tidy-undo

**1,200개가 쌓인 다운로드 폴더를 내 프로젝트 이름으로 나눠 정리한다. 이름만
봐선 뭔지 모를 파일을 열어서 알아볼 수 있는 이름으로 바꾼다. 전부 한 줄로
되돌린다 — 이 코드에는 삭제가 없다.**

macOS용 [Claude Code](https://claude.com/claude-code) 파일 정리 스킬이자,
직접 돌릴 수 있는 파이썬 스크립트 모음. `PDF/`·`이미지/` 같은 확장자 폴더를
만드는 도구가 아니다. **그 파일이 내 어느 프로젝트 자료인지**를 판단해서 거기
넣는다.

---

## 무엇을 얻는가

### 1. 확장자가 아니라 프로젝트로 나뉜 다운로드 폴더

확장자로 나누면 어수선함이 자리만 옮긴다. `PDF/` 폴더는 아이콘만 봐도 아는
사실을 폴더 이름으로 한 번 더 알려줄 뿐이다. 정작 필요한 건 **한 프로젝트의
계약서·발표자료·참고논문 세 편·엑셀이 한자리에 있는 것**이다.

`tidy-undo`는 이미 있는 프로젝트 디렉토리들 — 그 이름과 그 안 파일명들 —
에서 어휘를 만들고, 흩어진 파일을 그 어휘에 대고 점수 매긴다. 1위가 2위를
일정 배수 이상 앞설 때만 옮긴다. 애매한 건 그 자리에 두고 목록으로 보고한다.

**정리 전** (실제 실행, `~/Downloads` 최상위 흩어진 파일 240개):

```
~/Downloads/
├── 2508.09736v1.pdf
├── 2507.05246v1.pdf
├── 2505.00668v1.pdf
├── KakaoTalk_Photo_2026-07-14-09-21-33.jpeg
├── 스크린샷 2026-08-03 오후 4.51.12.png
├── 에이전트경제_v6.pptx
├── 에이전트경제_최종.pptx
├── 에이전트경제_최종_최종.pptx
├── 정책국/                          ← 279개
├── 정책국 2/                        ← 위 폴더와 바이트 단위로 동일한 사본
└── … 흩어진 파일 232개 더
```

**정리 후** (같은 실행, 삭제된 것 없음):

```
~/Downloads/                         ← 흩어진 파일 72개. 확신이 안 서서 안 건드린 것들
├── _archive/
├── _cleaner_quarantine/
│   └── 정책국 2/                     ← 복제 폴더를 통째로 옮겨둔 것. 지운 게 아니다
└── 정책국/

~/Archive/                           ← 404개. 도구가 지어낸 이름이 아니라 내가 쓰던 이름 아래로
├── aioutlook/문서/
├── aichip/{문서, 메모, 이미지}/
├── agent-economy/발표/
├── pet-hwahae/{표, 데이터}/
├── humanize-ko/이미지/
└── … 프로젝트 폴더 33개 더
```

### 2. `2508.09736v1.pdf` → 그 논문의 진짜 제목

arXiv ID는 기계에겐 완벽한 파일명이고 사람에겐 쓸모없는 파일명이다.
`tidy-undo`는 파일을 열어 실제 제목을 찾아 개명 후보로 올린다. 제목은 싼
경로부터 네 군데서 찾는다 — arXiv API(파일명 안의 ID만 보낸다), PDF 자체
`/Title` 메타데이터, 첫 페이지에서 가장 큰 글씨, 첫 몇 줄.

**개명 대상은 현재 이름이 불투명한 것뿐이다.** arXiv ID, UUID, 긴 16진수,
카메라·메신저가 붙인 숫자 이름. 사람이 지은 이름은 목록으로만 보여주고
건드리지 않는다. 내 `v7`, `3교본` 같은 표기는 내 기억이 걸려 있는 정보라서
도구가 임의로 없애면 안 된다.

같은 실행의 실제 결과 — 82건 개명, 실패 0:

```
2507.05246v1.pdf  →  When Chain of Thought is Necessary, Language Models Struggle to Evade Monitors.pdf
2504.06196v1.pdf  →  TxGemma： Efficient and Agentic LLMs for Therapeutics.pdf
2501.09223v1.pdf  →  Foundations of Large Language Models.pdf
2504.01848v1.pdf  →  PaperBench： Evaluating AI's Ability to Replicate AI Research.pdf
```

제목 추출 79건 중 75건은 arXiv API, 2건은 PDF 메타데이터, 1건은 arXiv 제목
검색, 1건은 표지에서 가장 큰 글씨.

### 그 과정에서 같이 되는 것

- **중복 파일 찾기** — 내용 해시로 잡으니 이름이 달라도 걸린다. 중복은 격리
  폴더로 가고, 휴지통으로는 가지 않는다.
- **복제된 폴더 찾기** — `정책국`과 `정책국 2`, 각각 279개. 눈으로 대조하면
  반나절이고 해시 집합 비교로는 순식간이다.
- **버전 난립 정리** — `v6`, `최종`, `최종_최종`. "최종"이라는 단어를 믿지
  않고 시각과 해시로 최신을 고른다. `v6`이 `최종`보다 나중인 경우가 흔하다.
- **민감 파일 점검** — 인감증명서·신분증 사본·계약서·복구 코드가 다운로드
  폴더에 평문으로 남아 있는 일이 흔하다. 이건 **옮기지 않고 목록으로만
  보고한다.** 어디에 둘지는 본인만 정할 수 있다.

## 왜 내 파일을 맡겨도 되는가

요즘은 AI 정리 도구가 다 "옮기기 전에 미리보기"와 "원클릭 되돌리기"를
내세운다. 그건 프롬프트나 소개 페이지에 적힌 약속이다. 아래는 저장소에
실제로 들어 있는 것이고, 각각 1분 안에 직접 확인할 수 있다.

**삭제가 없다.** "가급적 삭제하지 않는다"가 아니라 호출 자체가 없다.

```bash
grep -rn "os.remove\|shutil.rmtree\|send2trash\|\brm -" scripts/
# scripts/selftest.py:500:  shutil.rmtree(sb, ignore_errors=True)   # 테스트 샌드박스만 정리
```

딱 한 건, 테스트 하네스가 자기가 만든 임시 디렉토리를 치우는 자리다.
스캔·계획·이동 경로에는 무엇도 지울 수 있는 코드가 없다.

`scripts/apply.py`에 `os.unlink`가 일곱 번 나오는데 전부 용처가 분명하다 —
이동의 후반부 2회(목적지 링크가 확인된 다음에야 원본을 놓는다), 볼륨 간 이동의
임시본 2회, 대소문자 판정용 프로브 파일 1회, 자기 락 파일 2회.
`os.rmdir`는 `undo`에 한 번, 그것도 **이번 실행이
직접 만든 빈 폴더**에만 쓴다. 원래 있던 폴더는 건드리지 않는다. 격리한 것을
휴지통으로 보내는 건 별도 명령이고, 격리 폴더를 직접 확인한 뒤 따로 요청해야
실행된다.

**승인은 "네"가 아니라 해시다.** `apply.py verify`가 계획 파일에서 뽑은 토큰을
출력한다. `apply.py run`은 그걸 다시 계산해서 다르면 아무것도 옮기지 않는다.
승인한 뒤 계획을 한 줄만 고쳐도 실행이 거부된다 — 경고가 아니라 거부다.
그래서 **내가 읽은 계획**과 **실제로 실행된 계획**이 어긋날 수 없다. 중간에
모델이 마음을 바꿔도 마찬가지다.

**덮어쓰기가 불가능하다.** 같은 볼륨 안에서는 `os.link` 다음 `os.unlink`로
옮긴다. `os.link`는 대상이 이미 있으면 실패하므로, 덮어쓰기는 "안 하도록
조심하는 것"이 아니라 구조적으로 일어날 수 없다. 원본은 새 자리가 확인된
뒤에만 사라진다. 볼륨을 넘을 때는 임시본 복사 → 크기 검증 → 링크 → 그제서야
원본 정리 순서다. 이름이 겹치면 ` (2)`로 비켜간다. 하드링크 파일은 볼륨 간
이동을 거부한다(링크가 끊기므로).

**되돌리기는 추측이 아니라 재생이다.** 모든 실행이 매니페스트를 남기고, 한
줄로 역재생한다.

```bash
python3 scripts/apply.py undo _work/_runs/<run_id>/manifest.json
```

정리 이후 내용이 바뀐 파일, 원래 자리에 다른 게 들어선 경우는 건드리지 않고
사유와 함께 보고한다.

**강제종료돼도 길이 끊기지 않는다.** 모든 이동은 실행 **전에** `fsync`로
저널에 기록된다. 그래서 매니페스트가 쓰이지 못한 채 죽어도 저널만으로
되돌릴 수 있다. `undo`에 매니페스트 대신 실행 디렉토리를 넘기면 된다.

```bash
python3 scripts/apply.py undo _work/_runs/<run_id>/
```

검증: 3,000건짜리 계획을 963건 이동한 시점에 `SIGKILL`로 죽였고,
3,000건 전량이 복원됐다(잔류 0). 죽은 프로세스가 남긴 락 파일은 다음 실행이
그 PID의 생존을 확인한 뒤 회수한다.

**적대적 자가 테스트 23개, 직접 돌려볼 수 있다.** NFD 한글 파일명, 공백,
따옴표, 세미콜론, 백틱, 개행이 들어간 파일명, 대소문자 무시/구분 파일시스템
양쪽에서의 이름 충돌(이걸 위해 `hdiutil`로 실제 디스크 이미지를 만든다),
심볼릭 링크와 순환 링크, 하드링크, 위조 토큰, 승인 후 변조된 계획, 권한 거부,
살아 있는 락, 주인 없는 락, 디스크 풀, 그리고 위의 `SIGKILL` 복구까지.

```bash
python3 scripts/selftest.py
#   23/23 통과
```

전부 임시 샌드박스에서 돌고 끝나면 스스로 지운다.

## 설치

macOS와 파이썬 3.10 이상이 필요하다. 서드파티 패키지는 둘뿐이고 그나마 PDF를
읽을 때만 쓴다. 나머지 — 스캔·해시·중복탐지·분류·계획·이동·되돌리기·자가
테스트 — 는 전부 표준 라이브러리다.

```bash
git clone https://github.com/<you>/tidy-undo.git
cd tidy-undo
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python3 scripts/selftest.py      # 실제 파일을 겨누기 전에 23/23을 먼저 본다
```

Homebrew 파이썬은 [PEP 668](https://peps.python.org/pep-0668/)을 강제하므로
venv 밖에서 `pip install`을 하면 `error: externally-managed-environment`로
막힌다. 위 venv를 쓰거나 `pip install --user --break-system-packages -r
requirements.txt`를 쓰면 된다. PDF 제목 추출을 안 쓴다면 의존성 없이도 전부
동작한다.

mkdir -p ~/.claude/skills/cleaner

스킬이 그렇게 쓰여 있다.

### 스크립트를 CLI로 직접 쓰기

스크립트는 전부 결정적이고 Claude의 존재를 모른다. 마지막 줄 전까지는 전부
읽기 전용이다.

```bash
python3 scripts/scan.py ~/Downloads -o _work/inventory.jsonl --max-depth -1
python3 scripts/dedup.py _work/inventory.jsonl -o _work/dupes.json
python3 scripts/classify.py _work/inventory.jsonl -o _work/classified.jsonl

python3 scripts/plan.py --inventory _work/inventory.jsonl \
  --classified _work/classified.jsonl --dupes _work/dupes.json \
  --root ~/Downloads -o _work/plan.json --do quarantine,version

python3 scripts/apply.py verify _work/plan.json     # 승인 토큰을 출력한다
# _work/plan.json 을 직접 읽어보고 나서:
python3 scripts/apply.py run _work/plan.json --token <토큰> --runs-dir _work/_runs
```

| 스크립트 | 하는 일 | 네트워크 |
|---|---|---|
| `scan.py` | 읽기 전용 인벤토리. `.app`·`.photoslibrary` 패키지는 파일 1개로, 심볼릭 링크는 따라가지 않고, iCloud 미다운로드 파일은 열지 않는다. 1,500개에 0.2초 | 없음 |
| `dedup.py` | 완전중복·폴더 복제쌍·버전 계보 | 없음 |
| `classify.py` | 프로젝트 귀속. `--no-home-scan`으로 보수적 모드 | 없음 |
| `retitle.py` | PDF 제목 추출·개명 후보. `--no-network`로 로컬만 | arXiv |
| `extract.py` | pdf·hwp·hwpx·pptx·docx·xlsx·md 앞부분 텍스트 | 없음 |
| `sensitive.py` | 민감 문서 탐지. 보고만 하고 옮기지 않는다 | 없음 |
| `plan.py` | 계획 생성. `--do archive,quarantine,version,rename,relocate,sensitive` | 없음 |
| `apply.py` | `verify`/`run`/`undo`. 쓰기를 하는 유일한 스크립트 | 없음 |
| `selftest.py` | 샌드박스 적대적 테스트 23건 | 없음 |

`plan.py`와 `apply.py`는 `--root`로 지정한 디렉토리 밖으로 못 나간다. `~`,
`/`, `/Users`, `/Volumes`는 스코프로 지정할 수 없다.

한글 문서 쪽 덤: `extract.py`는 **HWP·HWPX**(한컴)를 의존성 0의 표준
라이브러리 파서로 읽는다. Spotlight의 이 두 포맷 색인율은 정확히 0%라
`mdfind`로는 안을 들여다볼 수 없다 — `.hwp`가 가득한 폴더가 다른 모든
도구에게 사실상 빈 폴더로 보이는 이유다.

## 누구에게 맞는가

**맞는 경우:**

- 일이 이름 있는 프로젝트 단위로 나뉘고, 홈 어딘가에 그 디렉토리들이 이미
  있다. 분류기가 읽는 게 바로 그거다. 그게 작동 원리 전부다.
- 파일명이 대체로 서술적이다. 실측으로 약 95%는 파일명만으로 귀속이 되고,
  진짜 내용을 열어야 하는 건 3% 남짓, 확장자만으로 처분되는 건 1% 정도다.
  이름을 먼저 보고 내용은 최후에 여는 설계가 여기서 나왔다.
- 주제가 아니라 ID로 이름 붙은 논문·규격서·행정문서 PDF를 자주 받는다.
- 뭐가 옮겨지는지 먼저 보고 싶다.

**안 맞는 경우:**

- 홈에 프로젝트 구조가 없다. 배울 디렉토리가 없으면 분류기에 어휘가 없고,
  거의 전부가 `_미분류`로 남아서 손으로 정리하는 것과 다를 게 없다. **갈
  곳을 먼저 만들어야 한다.**
- 상시 자동화를 원한다 — 폴더 감시, 다운로드마다 발동하는 규칙. 그건
  [Hazel](https://www.noodlesoft.com/)이나
  [organize](https://github.com/tfeldmann/organize)의 영역이고, 그쪽이 이
  도구보다 낫다. 아래 비교표 참고.
- GUI를 원한다. 이건 스킬과 스크립트다.
- 파일명을 LLM에 넘기고 싶지 않다. 스캔·해시·중복탐지·이동은 순수
  파이썬이지만 "이게 어느 프로젝트 거냐"는 판단 단계는 모델 호출이다.
- Windows·Linux를 쓴다. 스캐너가 패키지·iCloud placeholder·대소문자 판정에서
  macOS 고유 동작에 기댄다.

## 다른 도구와의 관계

깎아내리려는 게 아니다. 인접한 문제를 풀고, 몇 가지는 이 도구보다 낫다.

| | tidy-undo | [Hazel](https://www.noodlesoft.com/) | [organize](https://github.com/tfeldmann/organize) | [llama-fs](https://github.com/iyaja/llama-fs) | 상용 AI 정리앱 |
|---|---|---|---|---|---|
| **내 프로젝트 이름**으로 묶기 | 홈에서 학습 | 아니오 — 직접 규칙 작성 | 아니오 — 직접 규칙 작성 | 추론한 주제로 | 추론한 카테고리로 |
| 백그라운드 상시 실행 | 아니오, 요청할 때만 | 예 | 예(스케줄) | 아니오 | 제품마다 |
| 불투명한 PDF를 내용으로 개명 | 예, arXiv 조회까지 | 아니오 | 아니오 | 예 | 예 |
| 도구에 삭제/휴지통 기능 | **없음** | 있음 | 있음 | 있음 | 대개 있음 |
| 되돌리기 | 매니페스트 역재생, `kill -9`도 복구 | Finder 실행취소, 최선노력 | 없음 | 없음 | 대개 세션 단위 |
| 승인이 그 계획에 묶여 있는가 | 예, 해시 토큰 | 해당 없음 | 해당 없음 | 아니오 | 미리보기 화면 |
| HWP·HWPX 읽기 | 예 | 아니오 | 아니오 | 아니오 | 아니오 |
| 저장소 내 적대적 테스트 | 23건 | 해당 없음 | 있음 | 없음 | 해당 없음 |
| 가격 | 무료, MIT | 유료 | 무료, MIT | 무료, MIT | 대개 유료 |

**반복적이고 규칙이 명확한 문제라면 규칙 엔진을 쓰는 게 맞다.** "이 발신인의
청구서 PDF는 항상 저 폴더로"는 판단이 아니라 규칙이고, Hazel이나 `organize`가
더 빠르고 싸고 모델도 필요 없다. 이 도구는 **이미 쌓여버렸고 아무도 규칙을
써두지 않은 더미**를 위한 것이다.

## 알려진 한계

이제 본인 파일을 겨눌 참이니 있는 그대로 적는다.

- **맥 한 대, 사용자 한 명, 로케일 하나.** 위 수치는 전부 한 대에서 나왔다.
  외장 디스크·exFAT 볼륨·회사 관리 기기·비한국어 로케일에 대한 방어 코드는
  작성돼 있고 단위 테스트도 있지만 실제 환경을 만난 적이 없다. 본인 맥에서
  `selftest.py`를 먼저 돌리고, 첫 실행은 백업이 있는 상태에서 하라. 지금 가장
  값진 기여는 **두 번째 맥에서 온 버그 리포트**다.
- **생성되는 폴더 이름이 한국어다.** `scripts/plan.py` 상단의 `KIND_DIR` 맵에
  `문서`·`발표`·`이미지` 등이 하드코딩돼 있고, 기본 아카이브 목적지는
  `_정리됨`이다. 다른 로케일에서 크래시는 없지만 폴더 이름이 한국어로 나오는데,
  이건 "사용자 어휘로 폴더명을 짓는다"는 이 도구 자신의 목표와 어긋난다.
  사전 하나이니 고쳐 쓰면 된다.
- **스크립트의 콘솔 출력이 한국어다.** 진행 표시, 거부 사유, 자가 테스트
  리포트가 전부 한국어 문자열이다. 다만 스크립트가 내보내는 JSON —
  인벤토리·계획·매니페스트 — 의 키는 전부 영어라 파싱하는 쪽은 영향이 없다
  (계획 안의 사람이 읽는 `reason` 값만 한국어다). 콘솔 출력 영문화는 진행 중.
- **민감 파일 탐지는 한국 서식 위주다.** `sensitive.py`는 한국 신분증·증명서·
  금융·법률 서식을 인식한다. 영어 패턴은 password·API key·NDA·passport 같은
  뻔한 것뿐이라 미국 SSN, EU 신분증, 대부분의 비한국 공문서를 놓친다.
  **"탐지 안 됨"을 "민감한 게 없음"으로 읽으면 안 된다.**
- **분류 임계값이 한국어 복합어에 맞춰져 있다.** `--min-score`와 `--margin`은
  한국어 데이터셋에서 보정한 값이다. 영어 파일명도 처리되지만(한글 3-gram과
  영문 단어 토큰을 함께 쓴다) 다른 언어에서는 재보정이 필요할 수 있다.
- **`classify.py`가 기본값으로 홈을 폭넓게 읽는다.** 어휘를 만들려고 `~`의
  숨김 아닌 최상위 디렉토리를 전부 훑고 각 디렉토리 안의 파일·폴더 이름을 최대
  600개까지 읽는다. 이건 메모리에만 있고 디스크에 쓰이거나 어디로 전송되지
  않는다. 다만 결과물 `classified.jsonl`에는 매칭된 토큰이 근거로 남는데, 이
  조각이 다른 프로젝트의 파일명에서 나온 것일 수 있다. 그 파일을 공유하거나
  스크린샷 찍을 때 유의하라. `--no-home-scan`을 주면 홈 순회를 아예 끄고
  `--project-dir`로 지정한 것만 쓴다(대신 자동 확정되는 비율이 떨어진다).
- **`retitle.py`는 arXiv와 통신한다.** 파일명이 arXiv ID 패턴이면 그 ID —
  파일이 아니라 공개 식별자 — 를 `export.arxiv.org`로 보낸다. 드문 폴백
  경로에서는 PDF에서 뽑은 제목 조각(최대 10단어)을 검색어로 보낸다. **파일
  내용에서 파생된 것이 밖으로 나가는 유일한 경로가 이것뿐이고**, 그나마 이미
  공개 프리프린트처럼 이름 붙은 파일에만 해당한다. `--no-network`로 둘 다
  끈다. 다른 스크립트는 네트워크를 전혀 쓰지 않는다.
- **파일명은 모델 컨텍스트로 들어간다.** Claude Code가 판단 단계를 돌 때,
  규칙으로 확정되지 않은 파일들의 **이름**이 모델에 전달된다. 내용은 추출
  단계를 명시적으로 요청하지 않는 한 전달되지 않는다. 그것도 곤란한 데이터라면
  스크립트를 직접 쓰고 판단은 사람이 하면 된다 — 분류 판단 말고는 전부 모델
  없이 돌아간다.
- **`~/Pictures`는 의도적으로 거절한다.** 그 안의 거의 전부가
  `Photos Library.photoslibrary` 패키지 내부이고, 파일시스템으로 건드리면
  라이브러리가 깨진다. 스킬은 이 스코프를 거절한다. 스크립트를 직접 호출하면
  그 가드를 우회하게 되니 하지 마라.
- **중단된 실행을 이어서 하지 마라.** 저널로 복원한 뒤에는 스캔부터 다시
  하라. 계획이 기반한 스냅샷이 이미 어긋나 있다.

## 기여

지금은 기능보다 **두 번째 맥에서 온 버그 리포트**가 값지다. 특히 비한국어
로케일, 외장·네트워크 볼륨, 대소문자 구분 파일시스템, 회사 관리 맥, iCloud
Drive placeholder가 얽힌 경우.

`scripts/` 아래를 고쳤다면 실제 파일에 닿기 전에 `python3 scripts/selftest.py`가
23/23이어야 한다. 실행기를 고치면서 `selftest.py`에 케이스를 추가하지 않은 PR은
추가를 요청받는다.

의도적으로 범위 밖인 것들과 그 이유:

- **파일 삭제.** 격리 폴더와 Finder면 충분하다. 삭제 호출이 없다는 사실 자체가
  이 도구의 기능이다.
- **사람이 지은 파일명의 자동 개명.** 내 `v7`·`3교본` 표기에는 도구가 못 보는
  정보가 실려 있다. 불투명한 이름만 바꾼다.
- **수정시각 기준 자동 아카이브.** 다운로드 폴더는 활성 작업면이다. 오래된
  것이 덜 중요하다는 보장이 없다.
- **전량 확장자 폴더 분류.** 경로만 길어지고 정보는 늘지 않는다.
- **git 워킹트리 내부 재배치.** 미커밋 작업이 사라진다. 프로젝트 디렉토리는
  불가분 단위로 다룬다.
